# v0.3.0 — Health Contracts and Smoke-Test Rollback

Status: released on 2026-11-05.

## Release intent

`v0.3.0` strengthens the Docker Compose blue/green baseline at the boundary
between health validation and traffic promotion. It adds deterministic offline
contracts for Compose runtime expectations and restores the previous upstream
automatically when a public smoke test fails after traffic has switched.

## Highlights

- A failed post-promotion smoke test now restores Nginx to the previous color
  before the deployment command exits. The active-color marker is updated only
  after the rollback reload succeeds, while the failed candidate remains
  available for diagnosis.
- New offline contracts validate Compose service resource limits, health-check
  timing, health endpoint metadata, JSON health response semantics, dependency
  restart propagation, and proxy cache-bypass behavior.
- Unit coverage exercises successful rollback, Nginx reload fallback, and the
  dual-failure path where both the smoke test and automatic rollback fail.
- GitHub Actions use immutable commit SHAs, read-only validation permissions,
  and Ubuntu 26.04 runners. Daily automation is aligned to one 08:00
  Asia/Tehran run and preserves the configured Git identity.

## Compatibility and upgrade notes

- The package version advances to `0.3.0`; Python 3.10 or newer remains
  required.
- `python3 -m compose_zero_downtime`, the installed `compose-zero-downtime`
  command, and `deploy/blue-green-deploy.sh` remain supported entry points.
- The new contract validators are additive and operate on supplied metadata.
  Existing pipelines can adopt them incrementally.
- No persisted state, Compose schema, or deployment-environment migration is
  introduced.
- After a smoke-test rollback, the rejected candidate remains running for
  diagnostics. Operators should remove it only after preserving useful
  evidence and confirming the restored color is healthy.

## Known limitations

- Offline contracts validate supplied configuration and evidence; they do not
  prove that a live container, dependency, or health endpoint behaves as
  declared.
- Automatic rollback depends on a working Nginx reload or restart path. If the
  rollback also fails, the command reports both failure contexts and requires
  operator recovery.
- Default CI does not perform a privileged live deployment, production traffic
  switch, or destructive rollback drill.
- “Zero downtime” remains conditional on the documented health-check, proxy,
  capacity, statelessness, and backward-compatible migration assumptions.

## Rollback

This release adds validation policies and changes post-promotion failure
handling, but performs no data migration. A downstream pipeline can pin its
checkout or package dependency to `v0.2.0` while an adoption issue is
investigated. Preserve the last healthy color and its immutable artifacts, and
do not bypass a failed smoke test or rollback result merely to complete a
version rollback.
